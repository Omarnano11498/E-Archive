# الأرشيف الإلكتروني - WPF / C#

## المتطلبات
- Windows 10/11
- .NET 8 SDK أو أحدث إصدار LTS متوافق
- اتصال إنترنت أول مرة لاستعادة حزم NuGet

## التشغيل
1. فك ضغط الملف.
2. افتح `EArchive.csproj` في Visual Studio 2022.
3. نفّذ Restore NuGet Packages ثم Build ثم Run.

## التخزين
- قاعدة البيانات: `%LOCALAPPDATA%\\EArchive\\archive.db`
- الملفات: `%LOCALAPPDATA%\\EArchive\\Files\\yyyy\\MM\\`
- يتم استخدام اسم داخلي فريد لكل ملف لتجنب تعارض أسماء الملفات.
- استخدم نسخاً احتياطية دورية لقاعدة البيانات ومجلد Files معاً.

## المحتويات
- `Models/ArchiveRecord.cs`: كيان السجل.
- `Data/ArchiveRepository.cs`: استعلامات SQLite ذات المعاملات والفهارس.
- `Services/FileStorageService.cs`: التحقق من الامتداد والنسخ المتدفق للملفات.
- `Services/ExcelExportService.cs`: تصدير البيانات إلى XLSX.
- `MainWindow.xaml` و`.cs`: الواجهة وربط الخدمات.

## ملاحظات مهمة قبل الاستخدام المؤسسي
- هذا نموذج تطبيقي أولي قابل للبناء والتطوير، وليس نظاماً جاهزاً للاعتماد المؤسسي دون مراجعة واختبارات.
- البحث الحالي يستخدم LIKE؛ فهرس العنوان قد لا يستفيد منه الاستعلام الذي يبدأ بـ `%`. عند تضخم البيانات استخدم SQLite FTS5 للبحث النصي، وطبّق Paging بدلاً من جلب آلاف الصفوف.
- تصدير ClosedXML يجمع المصنف في الذاكرة؛ للتقارير الكبيرة جداً استخدم تصديراً متدفقاً أو قسّم التقرير.
- قاعدة SQLite مناسبة لجهاز أو استخدام محدود. للعديد من المستخدمين المتزامنين عبر الشبكة استخدم SQL Server/PostgreSQL وتخزين ملفات مركزي بصلاحيات مناسبة.
- ينبغي إضافة تسجيل دخول وصلاحيات وأثر تدقيق (Audit Log)، وسياسة استرجاع عند فشل قاعدة البيانات بعد نسخ الملف، وفحص مضاد للبرمجيات الخبيثة، وتشفير النسخ الاحتياطية قبل الاستخدام الرسمي.
- لا يُعد تغيير امتداد الملف أو التحقق من الامتداد فحصاً لمحتوى الملف؛ لا تفتح ملفات غير موثوقة دون حماية.
